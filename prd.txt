# Product Requirements Document (PRD)
# Two Digit System — Official Website

**Document Version:** 1.0  
**Product Name:** Two Digit System  
**Product Type:** Independent Software Studio Website  
**Platform:** Web  
**Primary Audience:** Individuals, businesses, and software users  
**Technology Stack:** Next.js, TypeScript, Tailwind CSS, shadcn/ui  
**Document Status:** Initial Product Specification

---

## 1. Product Overview

### 1.1 Introduction

Two Digit System is an independent software studio focused on developing useful digital products, including Android applications and web applications.

The website will serve as the official digital presence of Two Digit System.

It will showcase products developed by the studio, provide information about available development services, establish brand credibility, and offer visitors a way to contact the developer.

The website should communicate professionalism, technical capability, simplicity, and reliability.

### 1.2 Product Vision

Build a professional digital platform where users can discover, explore, and use software products developed by Two Digit System.

The website should become the central destination for all current and future applications and software products.

### 1.3 Brand Positioning

**Brand Name:** Two Digit System

**Brand Category:** Independent Software Studio

**Primary Tagline:** Ideas into digital products.

**Brand Description:**

Two Digit System develops practical Android applications and modern web solutions designed to solve real-world problems through thoughtful design, modern technology, and user-focused development.

### 1.4 Core Business Objectives

1. Establish a professional software development brand.
2. Showcase all Android and web applications in one place.
3. Increase product visibility and discoverability.
4. Generate enquiries for custom software development.
5. Provide dedicated product information, support, and legal pages.
6. Build trust with potential users and customers.
7. Create a scalable platform for future products.

## 2. Goals and Non-Goals

### 2.1 Primary Goals

- Create a professional and modern company website.
- Display Android and web products.
- Provide individual landing pages for every product.
- Present available development services.
- Generate enquiries through a contact form.
- Support SEO and search engine indexing.
- Provide responsive experiences on desktop, tablet, and mobile.

The initial version will NOT include:

- Customer login or registration.
- Subscription management.
- Online payments.
- Customer dashboard.
- Admin dashboard.
- Complex CMS.
- Project management functionality.
- E-commerce functionality.
- User-generated reviews.
- Community features.

These features may be considered in future versions if business requirements justify them.

# 7. Technical Requirements

## 7.1 Technology Stack

| Layer | Technology |
|---|---|
| Framework | Next.js App Router |
| Language | TypeScript |
| UI Library | React |
| Styling | Tailwind CSS |
| Components | shadcn/ui |
| Icons | Lucide React |
| Animation | Motion |
| Form Handling | React Hook Form |
| Validation | Zod |
| Email | Resend |
| Theme | next-themes |
| Deployment | Vercel |
| Package Manager | pnpm |

Use stable versions compatible with one another at implementation time.

## 7.2 Rendering Strategy

Use:
- Server Components by default.
- Client Components only when interaction requires them.
- Static generation for product pages where possible.
- Dynamic rendering only when required.

The marketing website should prioritize fast loading and search engine accessibility.

## 7.3 Content Management

For the MVP, product information will be maintained through typed TypeScript data files.

No database or CMS is required initially.

Future options:
- Sanity.
- Payload CMS.
- A custom administration dashboard.

## 7.4 Data Model

Define a reusable Product type.

Example:

```typescript
export type ProductPlatform =
  | "android"
  | "web"
  | "both";

export type ProductStatus =
  | "live"
  | "beta"
  | "in-development"
  | "coming-soon"
  | "maintenance"
  | "archived";

export interface Product {
  id: string;
  name: string;
  slug: string;
  tagline: string;
  description: string;

  icon: string;
  coverImage?: string;

  platform: ProductPlatform;
  status: ProductStatus;

  category: string;
  featured: boolean;

  features: {
    title: string;
    description: string;
    icon?: string;
  }[];

  screenshots: {
    src: string;
    alt: string;
  }[];

  links: {
    website?: string;
    playStore?: string;
  };

  supportUrl?: string;
  privacyUrl?: string;
  termsUrl?: string;

  seo: {
    title: string;
    description: string;
  };
}
```

Additional product fields can be introduced when real content requirements emerge.

## 7.5 API Requirements

Initial API endpoint:

`POST /api/contact`

Responsibilities:
- Validate request.
- Sanitize and validate input.
- Apply spam protection.
- Send enquiry email.
- Return structured response.
- Handle delivery failures safely.

No public product API is required in the MVP.

# 13. Non-Functional Requirements

### Reliability
The website must remain accessible and handle failures gracefully.

### Maintainability
Code should be modular, typed, and easy for one developer to maintain.

### Scalability
Adding a new product should require only adding product data and associated assets.

### Reusability
Reusable components must be used for product cards, navigation, footer, buttons, and page layouts.

### Compatibility
Support modern versions of Chrome, Firefox, Safari, and Edge.

### Localization
The MVP will use English as the primary language. The architecture should not prevent adding other languages later.

1. The website is publicly accessible using its production domain.
2. The homepage displays the brand and featured products.
3. All published products appear correctly in the product listing.

5. Every published product has an accessible detail page.
6. Product links point to the correct destinations.
7. Unavailable product links are not displayed.
8. Contact form submissions are validated.
9. Successful enquiries are delivered to the configured email.

# 20. Final Product Definition

Two Digit System will be a modern, product-focused independent software studio website.

It will provide a single destination for discovering software products, exploring their features, accessing applications, finding support, and contacting the developer for custom software projects.

The architecture will prioritize simplicity, maintainability, performance, SEO, and future extensibility.

The first release should focus on building an excellent public-facing website rather than introducing unnecessary backend complexity.

**Core principle: Build a polished product portfolio first. Expand into a larger software platform only when there is a real business need.**
